# Governance

Vetryn uses a lightweight maintainer-led governance model during its pre-alpha phase.

## Roles

- **Users** participate through issues, discussions, and feedback.
- **Contributors** submit documentation, tests, code, and design proposals.
- **Maintainers** review and merge changes, manage releases, moderate the community, and enforce the
  project's security and product principles.

The current maintainer list is in [`MAINTAINERS.md`](MAINTAINERS.md).

## Decision making

Routine decisions are made through pull request review. Material decisions should begin as a public issue
or discussion and, when accepted, be recorded in `docs/adr/`.

Material decisions include:

- public manifest or artifact formats;
- recommendation and abstention semantics;
- provider or security trust boundaries;
- backwards-incompatible API changes;
- licensing changes; and
- governance changes.

Maintainers seek rough consensus while retaining responsibility for coherent scope, security, and release
quality. If consensus cannot be reached, the project lead makes the final decision and documents the
rationale.

## Maintainer changes

Consistent contributors may be invited to become maintainers based on judgment, technical quality,
community conduct, and sustained participation. Maintainers may step down voluntarily or be removed for
extended inactivity, security concerns, or Code of Conduct violations.
